# Обновления Sombra

## Исследование и выбранный механизм

Discord описывает собственный updater, подписанные сборки, обновление по кнопке с перезапуском, проверку новой версии и delta-пакеты:
https://discord.com/blog/how-discord-seamlessly-upgraded-millions-of-users-to-64-bit-architecture
Новый Rust updater Discord также документирован здесь:
https://discord.com/blog/discord-linux-a-year-of-upgrades

Sombra использует официальный Tauri v2 updater через Rust API:
https://v2.tauri.app/plugin/updater/
Полные подписанные установщики NSIS вместо самописного delta-обновлятора. HTTPS, обязательная проверка подписи перед установкой, стандартное сравнение версий без downgrade, таймаут проверки 15 секунд, загрузки 10 минут, блокировка конкурентных операций. Проверка через 10 секунд после старта, каждые 4 часа и при восстановлении сети. Скачать и установить — отдельные явные действия. Во время звонка кнопка установки недоступна. Ошибка не блокирует чат; доступна повторная попытка. Загруженные данные находятся в памяти до установки/закрытия программы. После закрытия потребуется скачать снова.

UI сохраняет reference/picture-1.png, picture-2.png и picture-3.png: чёрные панели, серые границы, компактные кнопки и существующий диалог настроек. Новый раздел «Обновления», уведомление только при наличии релиза. В браузере обновлятор отключён.

## Что готово и что ещё нужно

В Sombra 0.1.0 используется HTTPS-канал подписанных обновлений на `sombra.mi-nerva.ru/updates/`. Доступ к исходникам и релизу на GitHub ограничен правами приватного репозитория. Проверка перехода между двумя установленными версиями станет возможна после следующего выпуска.

## Первый релиз Windows x64

1. Создать отдельный публичный репозиторий для релизов либо HTTPS-хранилище. Исходный код может оставаться приватным. Закрытый GitHub Releases без авторизации не подойдёт; токены нельзя встраивать в клиент.
2. Один раз создать ключ через `npm.cmd run tauri -- signer generate -w <путь-вне-репозитория>/sombra.key`. Приватный ключ и пароль сохранить в менеджере секретов и резервной копии. Не создавать новый ключ для каждого выпуска. Публичный ключ — содержимое .pub.
3. Задать окружение: `SOMBRA_UPDATER_PUBLIC_KEY` (содержимое .pub), `SOMBRA_UPDATER_ENDPOINT` (например HTTPS URL latest.json), `TAURI_SIGNING_PRIVATE_KEY` (путь/содержимое приватного ключа), `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (пароль ключа).
4. Синхронно увеличить версии в Cargo.toml, tauri.conf.json, package.json; обновить lock-файлы. Запустить `npm.cmd run test:updater`, `npm.cmd run build`, затем `npm.cmd run release:windows`. Скрипт проверяет настройки и включает NSIS currentUser, passive установку и подписанные updater artifacts. Сборка и упаковка требуют Windows toolchain/NSIS.
5. Установщик и .sig находятся в target/release/bundle/nsis. Загрузить установщик по неизменяемому HTTPS адресу конкретной версии. Подпись updater не заменяет Windows Authenticode: для доверия SmartScreen нужен отдельный сертификат подписи приложения.
6. Создать манифест: `node release-manifest.mjs <installer.exe> <HTTPS-URL-installer> [release-notes.txt]`. Скрипт предназначен для x64 NSIS; для других архитектур нужны отдельные сборки и записи platforms. Подпись читается из соседнего .sig.
7. Опубликовать latest.json последним, после проверки доступности установщика. Для GitHub — приложить установщик, .sig и latest.json к обычному опубликованному релизу (не draft/prerelease). Не публиковать секреты, data/, .env, FIRST-USER.txt, логи или QA-профили.
8. Первую настроенную подписанную сборку установить вручную; прежние сборки без updater сами её получить не смогут. Проверить переход на следующую версию в отдельном профиле/виртуальной машине: настройки, аккаунт и история сохраняются; плохая подпись, offline, повторная попытка и звонок обрабатываются правильно. Не менять identifier приложения.

## Выпуск и откат

Сначала тестовый релиз на отдельном канале, затем stable. При проблеме убрать ошибочный манифест/вернуть предыдущий для ещё не обновившихся клиентов; уже обновившимся выпустить исправление с большей версией. Не разрешать автоматический downgrade. Хранить предыдущие установщики, ключи и резервные копии данных. Обычная разработческая сборка не требует секретов и по-прежнему собирается через npm/cargo. В текущем проекте локальная база зависит от MINES_DATA_DIR/рабочей папки; перед первым распространением установщика явно определить постоянное расположение данных и перенос существующих локальных профилей.

## Настройка первого выпуска
Публичный ключ и адрес канала заданы в `tauri.conf.json`. Ссылки на установщик и манифест приведены в [RELEASE-STATUS.md](RELEASE-STATUS.md).
