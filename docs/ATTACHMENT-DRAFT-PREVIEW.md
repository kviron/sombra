# Превью неотправленного вложения

Картинка/файл отображается над строкой ввода внутри общей рамки композера. Фото получает локальную миниатюру, обычный файл — карточку с названием и фактическим размером. Крестик удаляет вложение или отменяет чтение; отправка остаётся отдельным действием. Backend по-прежнему принимает одно вложение на сообщение.

Сообщения уже используют локальную адаптацию shadcn Message/Bubble (`ui/shared/ui/message.tsx`). Она сохранена. Превью использует существующий Button, lucide и переменные темы; дополнительная UI-зависимость или формальный одноразовый shared-wrapper не добавляются.

## Безопасность и состояние

- До отправки файл не загружается на сервер. Тело черновика — прежний ограниченный raw base64; server attachment API не вызывается для локальной миниатюры.
- Распознавание PNG/JPEG/WebP/GIF — по байтам, не по расширению/MIME. Перед браузерным декодером выполняется существующая ограниченная проверка заголовков/размеров/кадров. SVG, HTML, неизвестные, повреждённые и слишком сложные изображения остаются карточками файлов, не встраиваются.
- Используется локальный Blob URL. Он создаётся в effect и освобождается при смене/удалении/размонтировании превью. Старое изображение не показывается под именем нового файла.
- Черновики остаются привязаны к исходному чату. Асинхронное чтение проверяет назначение, epoch, аккаунт и жизненный цикл компонента; удалённый/заменённый файл не возвращается после завершения старого чтения.
- Существующие textarea, Enter/Shift+Enter, вставка, drop, стикеры, slash-подсказки, typing и отправка не заменяются новой моделью ввода.

Изменение клиентское, не меняет API, production или опубликованную 0.1.17. Требуется новый клиентский выпуск.
