# Свой бот в комнате Mines

Владелец группы открывает комнату → значок бота вверху → вводит имя → «Создать подключение». Ключ показывается один раз. Он разрешает чтение и отправку сообщений только этой комнаты. Удаление бота немедленно отзывает ключ. В базе хранится только хеш. Участники видят имя и метку БОТ.

Для подключения ИИ нужен отдельно работающий сервис: модель не встроена в приложение и платный провайдер не активируется автоматически. Готовый `bot-worker.mjs` получает новые сообщения и вызывает ваш HTTP обработчик `AI_ENDPOINT`. Контракт обработчика: POST JSON `{text, messages}` → JSON `{text: "ответ"}`. API-ключ обработчика при необходимости задаётся в `AI_TOKEN`, только на машине бота. Обработчик может обращаться к локальной модели или выбранному провайдеру ИИ.

Переменные окружения: `MINES_API` (полный адрес /api общего сервера), `MINES_BOT_TOKEN`, `AI_ENDPOINT`, опционально `AI_TOKEN`. Запуск: `node bot-worker.mjs`. По умолчанию отвечает только на сообщения, начинающиеся с `/ai `; прошлую историю при запуске пропускает. Не отвечает другим ботам. Ошибки провайдера повторяются с задержкой; повторная отправка ответа после сетевого сбоя возможна (не exactly-once).

HTTP: POST /api, Authorization: Bearer <ключ>, Content-Type: application/json.
- `{op: "bot_poll"}` → `{data: {messages: [...]}}`, только сообщения своей комнаты.
- `{op: "bot_message", text: "Ответ"}` → `{data: {ok: true}}`.

Для нескольких компьютеров нужен один общий сервер по HTTPS. Разные локальные базы desktop-приложений не синхронизируются. Развёртывание общего сервера описано в BACKEND.md.
