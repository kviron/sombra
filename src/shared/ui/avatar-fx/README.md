# avatar-fx — рамки аватара и обложка-сцена на canvas

Клиентский движок украшений профиля для Sombra: пиксельные эффекты рисуются кодом на canvas (без GIF/PNG),
масштабируются nearest-neighbour (`image-rendering: pixelated`) и остаются чёткими в своей низкой сетке.

Две формы одного документа `v1`:

- **frame** — эффект вокруг/в углу аватара (огненное кольцо, слайм-питомец) или слой поверх обложки;
- **scene** — вся обложка является зацикленной пиксельной сценой: небо со звёздами, сияние, параллакс-холмы,
  бегущая земля и бегущий силуэт. Всё нарисовано кодом.

Каждый скопированный файл начинается с двухстрочного заголовка с коммитом; код под ним не менялся.

| id эффекта | откуда | зачем |
|---|---|---|
| `holy/divine-shield` | pixelfx | круглый обод; в палитре `ember` читается как огненное кольцо. Плёнка щита не видна: центр canvas замаскирован под круг аватара |
| `critters/slime` | pixelfx | прыгающий слайм с глазами, спорами и каплями — питомец в углу |
| `weather/aurora` | pixelfx | широкое ночное сияние: слой поверх обложки или небо сцены |
| `sombra/runner` | **наш код**, не pixelfx | силуэт бегуна из 1 px линий и прямоугольников (4-шаговый цикл бега), прокручиваемая земля и пыль. Готового бегущего персонажа в pixelfx нет: `moves/*` — это атаки, `critters/*` — прыгающие/летающие существа |

Почему для кольца не взят `fire/fire-ring`: это наземный AoE, нарисованный в перспективе пола (сплюснутый
эллипс). Вокруг круглого аватара он распадается на несколько искр слева и справа, а не в рамку.

## Формат документа v1

```json
{
  "v": 1,
  "target": "cover",
  "mode": "scene",
  "loop": true,
  "seed": 11,
  "layers": [
    { "effect": "weather/aurora", "palette": "aurora", "anchor": "fill", "intensity": 0.75 },
    { "effect": "sombra/runner", "palette": "ice", "anchor": "runner", "intensity": 0.9 }
  ]
}
```

| поле | тип | по умолчанию | смысл |
|---|---|---|---|
| `v` | `1` | — | версия формата; неизвестная версия — отказ |
| `target` | `avatar` \| `cover` | `avatar` | куда рисовать |
| `mode` | `frame` \| `scene` | `frame` | `scene` только для `cover`; на аватаре безопасно откатывается в `frame` |
| `loop` | boolean | `true` | зарезервировано; все текущие эффекты зациклены |
| `seed` | целое 0…4294967295 | `0` | детерминированное зерно эффекта |
| `layers` | массив ≤ 3 (avatar) / ≤ 3 (cover) | — | слои; лишние отбрасываются |

Слой:

| поле | тип | по умолчанию | смысл |
|---|---|---|---|
| `effect` | id из таблицы | — | неизвестный id отбрасывается |
| `palette` | имя палитры или массив 3–12 hex (`#rgb`/`#rrggbb`) | палитра эффекта | перекраска |
| `anchor` | `ring` \| `bottom-right` \| `bottom-left` \| `top-right` \| `top-left` \| `fill` \| `runner` | по эффекту | размещение |
| `scale` | 0.5…2 | `1` | размер canvas относительно базового |
| `intensity` | 0…1 | `0.8` | сила свечения и прозрачность слоя |
| `flip` | boolean | `false` | зеркалирование эффекта |

### Валидация (`normalizeDecoration`)

Чистая синхронная функция, ничего не бросает, не исполняет код из данных и не доверяет форме JSON:

- не объект / не массив слоёв / неподдерживаемая `v` → `ok:false`, `value:null`;
- неизвестный `effect` → слой отбрасывается; эффект не для этого `target`/`mode` → отбрасывается;
- неизвестный/неподходящий `anchor` → дефолт эффекта + предупреждение;
- неизвестная/недопустимая палитра → палитра эффекта + предупреждение; hex-массив проверяется регуляркой;
- `scale`/`intensity` клампятся, нечисла → дефолт + предупреждение; `seed` — только uint32;
- больше лимита слоёв → обрезка с предупреждением, жёсткий предел 8;
- `v` отсутствует — допускается с предупреждением (совместимость), но `v:2` — отказ;
- геттеры/прокси, бросающие при чтении, отвергаются целиком.

Результат: `{ok, value, warnings, errors}`; `warnings`/`errors` — `{code, layer?, detail?}`. `serializeDecoration`
даёт компактную JSON-форму для API (без функций и `undefined`).

## Геометрия и чёткость

| режим | сетка эффекта | CSS |
|---|---|---|
| ring (аватар) | `clamp(2 × avatarPx × scale, 48, 224)`² | 200 % × scale от аватара, центр замаскирован кругом аватара |
| corner (аватар) | 56×56 (родная сетка слайма, лужа обрезана на 2 ряда) | 80 % × scale, у угла |
| cover overlay | 320×107 (верхняя 3:1 полоса сияния) | 100 % × scale, `mix-blend-mode: screen` |
| scene | 320×107, полностью непрозрачная | 100 % × scale, обычный blend |

- Один пиксель эффекта ≈ один CSS-пиксель в ring-режиме; на DPR > 1 браузер увеличивает его целыми
  device-пикселями с `pixelated` — без сглаживания.
- Это пиксельная графика: чёткость сохраняется в её сетке, но эффект не становится векторным и не «бесконечно
  резким» при любом размере.
- Ring-маска (`radial-gradient`, вырезающий круг аватара) гарантирует, что эффект не рисуется поверх лица;
  corner-маска гасит края canvas, чтобы свечение не читалось прямоугольником.

## Производительность и приватность

- Один общий `IntersectionObserver` (rootMargin 96 px): движок, контекст и буфер пикселей создаются только при первой отрисовке слоя.
- Общий rAF-планировщик (`scheduler.ts`) обрабатывает изменения видимости пакетом: не более **4** одновременно анимируемых canvas, целевые 30 fps.
  Карточка профиля и образцы в выборе украшений получают слоты раньше фоновых аватаров. Остальные видимые слои получают статичный кадр (до 4 первичных статичных кадров за rAF) и сохраняют его при повторном появлении.
  `document.hidden` останавливает цикл; возврат продолжает анимацию без ускоренной прокрутки.
- Pixelfx запускается автоматически без кнопки, даже если WebView/RDP сообщает `prefers-reduced-motion: reduce`. Правило относится только к украшениям.
- Удаление компонента отменяет rAF/наблюдатели и убирает job; при нуле job слушатели снимаются.
- Никаких сетевых запросов, blob-URL, `eval`, `Function`, чтения чужих данных: вход — только документ украшения.
- Декор `aria-hidden`, `pointer-events: none`; клики по аватару не перехватываются.

## Интеграция

`ui/shared/ui/user-avatar.tsx` уже принимает необязательный `decoration`:

```tsx
<UserAvatar user={user} size="lg" decoration={user.decorations?.avatar} />
```

Без `decoration` компонент остаётся прежним (canvas не создаётся).

Для обложки (файл `ui/shared/ui/profile-cover.tsx`, отдельная зона) — один слой внутри `.profile-cover`:

```tsx
const decoration = user.decorations?.cover;
const scene = decoration?.mode === 'scene';
{decoration && <AvatarFrame decoration={decoration} target="cover" />}
{/* в scene-режиме обложка-картинка не нужна: сцена непрозрачна и сама является обложкой */}
{!scene && image && <img ... />}
```

`AvatarFrame` сам нормализует документ, поэтому с сервера можно отдавать как есть.

## Серверный контракт (ещё не реализован)

Хранение — отдельная задача; клиент к нему готов. Минимальный контракт:

- `UserDto` (все публичные пути: `me`/`state`/`login`/`register`/`directory`) получает
  `decorationSupported: true` и необязательное `decorations: {avatar?: Doc, cover?: Doc}`. Нет поля — нет украшений
  (как `cover`). Никаких файлов/бинарей: только JSON.
- Новая операция `set_profile_decoration { target: "avatar"|"cover", decoration: Doc|null }` — только человеческая
  сессия, только свой аккаунт, `null` удаляет. Возвращает `{user: UserDto}`. В `update_profile` поле не добавлять:
  `ProfileDto` отвергает неизвестные поля.
- Ограничения сервера (те же, что у клиента): `v===1`; `target` из двух значений; `mode` из двух; слоёв ≤ 3;
  `seed` uint32; `scale` 0.5–2; `intensity` 0–1; `effect` только из белого списка; `anchor` только допустимый для
  эффекта/цели; `palette` — имя из списка или 3–12 hex; `flip` boolean. Неизвестные ключи вырезать, не сохранять.
- **Размер:** сериализованный документ на цель ≤ **4096 байт** (фактический максимум сейчас — 789 байт для
  аватара с 3 слоями кастомных палитр и 249 байт для сцены). Больше — 400, без сохранения.
- Валидация сервера независима от клиента (defense in depth); клиент всё равно нормализует перед рендером.
- Никаких URL/функций/data-URI внутри документа; ошибки не должны возвращать сохранённый документ целиком в логах.
- Бэкап/миграция: отсутствующее поле = без украшения, переписывать старые записи не нужно.

## Ограничения этого шага

- Серверное хранение и UI выбора украшения не делались — только движок, формат и клиентский компонент.
- Вендорены три эффекта pixelfx; бегун — собственный примитивный спрайт Sombra, не pixelfx.
- `scene` доступен только для `cover`; `loop:false` зарезервирован (все текущие эффекты зациклены).
- Украшения сверх лимита остаются на статичном кадре, пока не освободится слот.
- Анимация в фоне вкладки останавливается целиком; при возврате продолжается с текущего времени.
