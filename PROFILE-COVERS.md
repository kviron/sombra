# Обложки профиля и общий crop Sombra

## Интерфейс

Обложка профиля стала выше: формат **3:1**, около 253 px при ширине карточки 760 px вместо прежних 118 px. Та же пропорция используется в редакторе и предпросмотре. Только аватар перекрывает край обложки; имя и статус находятся ниже картинки, в том числе при белой обложке.

В настройках профиля можно загрузить/удалить собственную обложку. Для обложки и обеих существующих загрузок аватаров (профиль, группа) используется **react-easy-crop 6.2.5**: перемещение изображения, масштабирование, сброс, отмена и применение. Для групп применение crop меняет только локальный черновик; серверная запись — после «Сохранить» с повторной проверкой права на аватар.

- Статичный исходник: PNG/JPEG/WebP до 20 МиБ, сторона до 8192 px, до 32 млн пикселей.
- Статичный аватар: PNG 256×256, до 256 КиБ.
- Статичная обложка: 1200×400, до 2 МиБ.
- GIF поддерживается **для обложек**, до 2 МиБ, до 2048 px по стороне, 240 кадров и 60 млн суммарных пикселей логических кадров. Анимированные PNG/WebP и GIF-аватары не заявлены и отклоняются.

GIF не проходит через статичный canvas: сохраняются исходные байты, задержки/циклы и процентная область crop. Изображение отображается в ограниченном блоке по этой области, поэтому анимация не теряется. Статичные картинки физически ресемплируются. EXIF-поворот/отражение JPEG учитывается одинаково в предпросмотре и результате.

## API и хранение

`UserDto` содержит `coverSupported:true` и необязательное маленькое `cover`:

```ts
{id,mime,width,height,crop:{x,y,width,height},animated,bytes}
```

В `state`, каталоге пользователей, `me`, login/register **нет тела обложки**. Файл запрашивается только при открытии профиля или собственного предпросмотра:

- `set_profile_cover {cover:{dataUrl,crop}}` — сохранить обложку текущего человека; `cover:null` — удалить. Ответ `{user}`.
- `profile_cover {user,coverId}` — тело текущей версии публичного профиля для авторизованного человека: метаданные, `user`, `data` (base64). Устаревший ID, несуществующий/отключённый адресат и bot bearer не дают доступ.

Файлы находятся в приватном каталоге данных `profile-covers`, под проверенными UUID, не на публичном статическом URL. SHA-256 проверяет содержимое; пути/симлинки/reparse не принимаются. Замена атомарна: ошибка до commit откатывает метаданные и удаляет новый файл, старый удаляется только после успешного commit. Обложки не относятся к TTL вложений чата и его локальному кэшу.

Сервер проверяет формат по сигнатуре и реальному ограниченному декодированию, MIME, размеры, число кадров, память, процентный crop и его пропорцию 3:1. Перед GIF-декодером отдельный bounded preflight проверяет **каждый исходный прямоугольник кадра**: кадр не может быть больше логического экрана и обходить суммарный pixel budget. SVG/HTML, URL и неограниченные анимации не принимаются.

Клиент дополнительно проверяет заголовки до передачи браузерному декодеру: PNG/IHDR, ограниченный JPEG/EXIF, согласование WebP VP8X/битстрима, GIF-контейнер. Дублирующиеся/противоречивые размеры отклоняются.

## Жизненный цикл

Обложки загружаются по ключу «аккаунт + профиль + версия», а не по новому объекту очередного poll. Опрос не перезапускает GIF и не скачивает его каждые две секунды. Запоздалый ответ другого аккаунта/версии игнорируется; object URL освобождается при закрытии/замене. Отмена crop не сохраняет изображение; черновики имени/биографии не теряются при сохранении картинки. Escape закрывает только crop и возвращает фокус в исходный выбор файла, не закрывая родительские настройки.

На старом сервере без `coverSupported` загрузка/удаление обложки отключены с пояснением; обычный аватар и новый редактор доступны. Для сохранения обложек в рабочих аккаунтах потребуется согласованное обновление сервера. Эта работа пока **только локальная**, без публикации/изменения production.
