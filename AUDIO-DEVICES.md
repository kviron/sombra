# Обнаружение аудиоустройств и удалённые сессии Windows

## Диагностика 17 ноября 2026

Реальная установленная Sombra и диагностический процесс находились в одной Windows-сессии. Прямой запрос Windows API показал:

- `WTSClientProtocolType = 2`: RDP, несмотря на переменную окружения `SESSIONNAME=Console`.
- `IMMDeviceEnumerator`: **1 активный endpoint вывода, 0 endpoint записи** в текущей сессии.
- `GetDefaultAudioEndpoint(eCapture, role)` для Console/Multimedia/Communications: `0x80070490` — нет устройства.
- `Audiosrv` и `AudioEndpointBuilder` работали; настройки конфиденциальности микрофона Windows разрешали доступ.
- Глобальный реестр содержал физические микрофоны, но это не доказывает их доступность процессам текущей RDP-сессии.

Следовательно, реальный `getUserMedia({audio:true}) → NotFoundError` согласуется с отсутствием переданного в RDP микрофона. Нельзя исправить это выдачей разрешений любым сайтам или подстановкой выдуманных WebRTC device ID. Никакие системные настройки, службы, default endpoints, политики и параметры RDP этой работой не изменялись. Микрофон не открывался для записи при диагностике.

Для передачи микрофона пользователь включает в клиенте удалённого рабочего стола: **Локальные ресурсы → Удалённый звук → Параметры → Запись удалённого звука → Записывать с этого компьютера**, затем переподключается и обновляет устройства. Названия могут отличаться у другого RDP-клиента. Альтернатива — запустить Sombra локально без удалённой сессии.

## Исправленная клиентская ошибка

В старом обработчике «Показать устройства» неудача пробы микрофона прерывала и обновление списка динамиков/камер. Теперь перечисление независимо от результата пробы; ошибка разрешения/микрофона сохраняется при успешном перечислении. Отказ разрешения не запускает попытки открыть другие микрофоны. Поздние временные потоки останавливаются, смена жизненного цикла не меняет закрытую панель.

Сохранённый недоступный device ID не заменяется автоматически — особенно во время звонка. Добавлена явная кнопка «Использовать по умолчанию» для микрофона, динамиков и камеры. Реальный захват в звонке и его выбранный микрофон не подменялись. Логические default/communications сохраняют смысл системного выбора.

Проверка **камеры** теперь запрашивает только `video` с `audio:false`, чтобы работающая камера не считалась неисправной из-за отсутствующего микрофона. Анализатор уровня не запускается на video-only потоке.

## Нативный контекст

Команда `audio_device_context` возвращает только:

```json
{"remoteSession":true,"inputs":0,"outputs":1,"defaultInput":false,"defaultOutput":true}
```

Значения в примере соответствуют обнаруженной сессии; они не захардкожены. Используются WTS и CoreAudio текущей сессии, не глобальные записи устройств. Нет имён, идентификаторов, записи звука, изменения разрешений или настроек. COM и память WTS освобождаются. Ошибки запроса возвращаются ошибкой, а не фиктивными нулевыми устройствами. В браузере/старой нативной версии отсутствие команды обрабатывается как неизвестный контекст.

Для RDP с нулём входов интерфейс объясняет отсутствие переданного микрофона, а не обещает, что разрешение или переподключение USB исправит RDP. Контекст обновляется при открытии, пользовательском обновлении и `devicechange`.

## Локальные проверки

- Нативные тесты контекста: **2 прошли**, включая реальный read-only запрос Windows и классификацию протокола 2.
- `check-audio-recovery-browser.mjs`: **10 сценариев прошли**, в том числе NotFound/NotAllowed с доступными динамиками, RDP-подсказка, явный сброс, камера без аудио и очистка временных потоков.
- Существующий `check-device-selection-browser.mjs`: **18 сценариев прошли**, исходные проверки не ослаблялись.
- Изолированный `check-voice-browser.mjs --devices-only`: прошёл проверку смены микрофона и маршрутизации выхода. Адаптация адресов/ожидания начальной загрузки описана в изолированном QA-отчёте; проверки RNNoise не запускались.
- В браузерных проверках media/native boundary подменяется явно. Это **не** доказательство реального положительного захвата физического микрофона: текущая Windows-сессия такого входа не предоставляет.

Работа локальная: production, установленный клиент и автообновление не обновлялись автоматически.
