# Регистрация команд самим сервисом бота

Новый v2 `bot_get_me.data.commandRegistrationSupported=true` разрешает сервису вызвать `bot_register_commands {commands:["model","sombra_confirm","sombra_answer"]}` с собственным Bearer token. Операция добавляет только отсутствующие имена, не удаляет/заменяет пользовательские команды и не меняет privacy, trust, установки, владельца или настройки моделей.

- Нет поля target bot/group: токен всегда выбирает своего бота; лишние поля запрещены.
- Только нелегаси-бот, включённый и с действующим токеном. Обычная human cookie не заменяет worker token.
- 1–32 уникальных входных имени, `[a-z0-9_]`, длина1–32, итоговый union≤32. Ошибка атомарна, повтор идемпотентен.
- Существующий owner-cookie `bot_set_commands` (замена списка) не менялся.
- Старая серверная версия не объявляет capability: плагин не должен отправлять неподдерживаемый RPC. В частности, bare `/model` в группе нельзя объявлять доступным только потому, что DM получает любой текст.

Три real-HTTP/API регрессии проверяют собственный Bearer, изоляцию другого бота, явную маршрутизацию `/model@username` только нужному боту в commands-only группе, сохранение пользовательских команд, malformed/overflow, legacy, rotation/delete/disable и отсутствие изменения политики/прав.

API и Rust binary пока только подготовлены к следующему согласованному выпуску. Текущий production backend0.1.17 capability ещё не имеет; `/model` логика плагина разрабатывается отдельно.
