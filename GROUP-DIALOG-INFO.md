# Название/аватар группового ЛС и поиск участников

Из «Информации о чате» создатель группового личного диалога (3–10 человек) может изменить название и аватар. Личные диалоги двух участников и диалоги с ботами не переименовываются этим API. Прочие участники видят информацию и поиск, но не редактирование. Сервер проверяет права независимо от кнопки.

## Сохранение

`update_dialog {dialog,revision,name?,avatar?}` возвращает обновлённый Dialog. Неизвестные поля, изменение владельца/состава и bot Bearer не принимаются. Ревизия обязательна, отсутствующая старая ревизия считается 0; конфликт возвращает HTTP409. Изменения сохраняются в общей БД и видны всем участникам. Ошибка записи откатывается общим backend request transaction.

Название обрезается по краям, ограничено 1–60 Unicode-символами, управляющие символы запрещены. Аватар — data URL PNG/JPEG/WebP, проверяемый полностью ограниченным декодером: до 500 КиБ, 2048×2048, 32 МиБ выделения. UI использует существующий квадратный crop до 256 КБ, даёт preview/удаление и не отправляет картинку до «Сохранить». Отмена не меняет сервер. Конфликт сохраняет пользовательский черновик для повторной попытки.

Sidebar, шапка и InfoDialog используют общий Dialog.avatar/name. Старые poll-ответы не откатывают подтверждённую metadata-ревизию; отсутствующие в новом state диалоги не восстанавливаются, новые owner/members не заменяются устаревшими.

## Поиск

`search_conversation_members {channel,query}` возвращает `{users:PublicUserDTO[]}` только из текущего разговора, после проверки членства. Публичные имя/логин сопоставляются без учёта регистра; скрытая почта — только по полному точному адресу (trim/lowercase). Чужие email не возвращаются, глобальный каталог не обыскивается. Read-only путь не обновляет БД, сессии или миграции.

UI ищет имена/логины локально и делает запрос только для полного email с debounce250мс. Устаревшие query/room/account ответы не меняют текущий список. Неизвестная почта не выдумывается и не раскрывается в строке участника. Статусы используют общий относительный peerStatus.

Новые state-capabilities `dialogMetadataSupported` и `conversationMemberSearchSupported` позволяют старому серверу оставить readonly/локальный поиск без неподдерживаемых RPC.

Проверено: 29 React/CDP сценариев с реальным изолированным mines-server, четырьмя синтетическими пользователями, crop, сохранением/видимостью у второго участника,403/409, приватностью и гонками. Production, клиентский установщик и Rust binary пока не обновлялись; требуется согласованный следующий выпуск.
